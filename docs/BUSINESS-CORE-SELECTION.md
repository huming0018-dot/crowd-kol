# KOL / 众包业务核心筛选

固定源：crowd-kol @ 0ce911159a4b2f6d78d9f19145deb958d4c5efd0。范围为 7 个 server/kol 业务脚本及 2 个 server/crowd Python 脚本的核心入口、输入输出和依赖；PR3 已审 _lib 不重做。SQL 迁移、线上数据、调度、渠道可达性未验收，不称全仓闭合交付。

|核心|功能/完整性与价值|去向|
|---|---|---|
|crowd_score|输入 rating/owner/task，输出 Beta 后验、CI、cell 内排名与版本。内置样本正常产 5 店，同输入复算相同；Beta(1,1)三分位符合均匀分布。校准恒等、note不入池、all/owner排名相同是明确骨架边界；远端写入DELETE后POST非事务。数学核心可运行，不等于完整评分产品。|留项目离线原型，不晋升模型或通用统计库，不恢复写入；成熟数学库优先于另造独立Beta包。|
|kol_monitor|视频记录→上海相关提及/歧义/线索；保留多分店候选、最长匹配及状态/帖子写入。项目流程实现存在，渠道/库与环境外部依赖未验；关键词情感不证明真实性。|留项目；不提通用实体/情感工具。|
|kol_router|开放mentions→守卫/独立KOL聚合→可选地图→队列。守卫与聚合可独立有意义；地图模块缺失有显式no_map_module出口，不能据此否定整个核心。状态缓存无保鲜、多个文件非事务。|留项目，不搬地图、配额或数据库。|
|kol_post_ingest|统一帖子→名称索引/提及→可选帖子和mentions写入；真实机械处理已实现。离线反例：两同名店被setdefault静默保留首店；“幸福饭店不好吃”判pos。不是可靠消歧或情感通用库。|留原项目参考实现和反例，不宣称质量完成，不因单项bug删除完整流程。|
|kol_identity|搜索结果+已知mid→handles计划→显式apply；有真实核对分支。静态发现merged.update(new)会改已有平台键，与“已写平台跳过”文案不符；同名本身也不是身份认证。|留项目参考，不提通用身份解析；未执行搜索/PATCH。|
|kol_trust_grade|人工精选池+watchlist→trust变更计划；精确/包含匹配实现完整，但包含兜底、首命中与短输入存在误归属风险。|留项目规则，不提可信度模型。|
|kol_context_backfill|title+summary中精确名字→前后40字；无匹配返回空。离线边界验证通过，数据库入口需既有表。|留项目小脚本，不为十行窗口另建工具库。|
|kol_cross真实路径|搜狗结果→标题指纹、线索池和状态；不硬绑作者。完整可用流程形态；去重实际只用归一标题，文案“+链接”不等于实现；状态坏文件当空、线索/游标分写风险留经验。|保留6个真实函数及CLI；未运行渠道或写文件主流程。|
|kol_cross三search占位|weibo_search/zhihu_search/douyin_search只恒定返回空数组+旧阻塞说明，没有采集核心；当前所有Python AST无名称或属性引用。|退出3个假能力接口和未使用移动UA；历史说明/probe保留，不添加新采集能力。|
|crowd_tracking|三表→任务/回流/活跃报告→可选通知/JSONL；聚合/渲染业务实现存在，notifier是仓外依赖，部分链缺依赖不等于聚合本身残缺。|留项目；不提通用通知或看门狗，不执行通知。|

四类结论：本批全部属项目业务/辅助，不新增模型、基建或通用工具。保留理由是有实际输入输出和业务语义，而非“能跑即全部合格”；质量反例仍限制后续使用。
